# Development Guide

## Architecture

`PCMigrationTool` is the elevated WinForms host. It owns UI controls, screen capture, command parsing, and dependency composition. `PCMigrationTool.Core` contains the testable workflow:

```text
Gather -> inventory/artifacts/profile copy -> manifest + report
Restore preparation -> account/domain/rename -> local UNC staging -> atomic state + cached executable
System resume -> Wi-Fi import -> user phase
User resume -> profile/artifacts/drives/printers -> guidance -> complete
```

The migration repository is always `<destination>\<HOST>_<dd-MM-yyyy>\PC_SWAP_INFO`. New profile data lives in `UserProfile`; legacy schema `1.0` manifests and layouts are read defensively. Do not move state, logs, or captured data outside this structure.

## Local Workflow

Use Windows 10/11 and the .NET 10 SDK:

```powershell
dotnet restore .\PCMigrationTool.sln
dotnet build .\PCMigrationTool.sln -c Release --no-restore
dotnet test .\PCMigrationTool.sln -c Release --no-build
dotnet publish .\src\PCMigrationTool\PCMigrationTool.csproj -c Release --no-build -o .\artifacts\publish
```

Run `artifacts\publish\PCMigrationTool.exe` as administrator. `scripts\Build-Release.ps1` performs the complete release pipeline and writes a ZIP plus SHA-256 checksum.

## Headless Examples

```powershell
.\PCMigrationTool.exe --gather --destination D:\Transfers `
  --allow-missing-browser-exports --result-file D:\gather-result.json

.\PCMigrationTool.exe --prepare-restore `
  --manifest D:\OLD-PC\PC_SWAP_INFO\manifest.json `
  --local-user technician --make-admin --result-file D:\restore-result.json
```

Passwords are accepted only through the GUI/native APIs; headless account creation intentionally does not expose a password argument. Resume commands are generated by `ResumeTaskService` and run from `%ProgramData%\PCMigrationTool`. `RepositoryStagingService` copies UNC-backed manifests and profiles to `%ProgramData%\PCMigrationTool\Repository`; the local state is authoritative during resume, with source-share state updates treated as best effort.

## Safety Rules

- Treat manifests as untrusted input; validate paths, usernames, hostnames, UNC mappings, and schema versions.
- Use `ProcessStartInfo.ArgumentList` or native Windows APIs. Never concatenate credentials into a command.
- Keep writes atomic and backwards-compatible. Unknown JSON properties must survive reads.
- A Robocopy exit code below 8 is success. Preserve its full transcript and fail on bit 8.
- Never auto-apply source IP settings to an unverified adapter or install unverifiable printer drivers.
- Do not commit migration outputs, logs, browser CSVs, state, credentials, or build artifacts.

The legacy `PCSwapTool.ps1`, Pester suite, PowerShell analyzer configuration, and validation script are retained for regression maintenance only.
